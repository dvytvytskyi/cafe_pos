Технічне завдання: Corgi Cafe POS (Деталізована Архітектура та Функціонал)

Цей документ описує повний спектр функціоналу та архітектуру проекту Corgi Cafe POS, базуючись на затвердженому scope та реалізованих інтерфейсних рішеннях. Він є вичерпною специфікацією, яка об'єднує бізнес-вимоги, системну архітектуру, ролі користувачів та глибоку логіку модулів.

1. Платформи, Мови та Доступність

Система побудована як кросплатформне рішення для покриття всіх потреб ресторанного бізнесу: від управління до самообслуговування клієнтів.

1.1. PC / Web-версія (Бек-офіс)

Повноцінна веб-панель для адміністрування, управління меню, фінансами та перегляду глибокої аналітики. Доступна на 4 мовах: Англійська, Іспанська, Каталонська, Російська. * Технологічний стек (Фактичний з package.json): React 19, Next.js 16 (App Router), Tailwind CSS v4, Framer Motion (Drag&Drop, мікроанімації), Chart.js (графіки дашборду), Mapbox GL (робота з картами), Lucide React (іконки). * UI/UX Патерни: Сучасний чистий дизайн, заокруглені картки, контекстні меню та модальний глобальний пошук (виклик через ⌘K). Зміна мови працює без перезавантаження сторінки через глобальний state.

1.2. Tablet / Phone App (PWA)

Оптимізована версія (Прогресивний веб-додаток) для touch-екранів, який встановлюється на планшети або смартфони персоналу. * Оптимізація під Touch: Великі кнопки, підтримка жестів (свайпи для закриття замовлень, pinch-to-zoom для карти столів). * Призначення для Офіціантів: Швидкий прийом замовлень безпосередньо біля столика, відправка чеків на кухню (маршрутизація), розрахунок. * Призначення для Менеджерів: Оперативний контроль залу, мобільний контроль, підтвердження скасування замовлень.

1.3. Клієнтська частина (User Side / E-menu)

Електронне меню (інтерфейс самообслуговування) з доступом по QR-коду. * Доступ: Здійснюється через сканування унікального QR-коду, закріпленого за конкретним столиком (згенерованого в системі). * Можливості: Перегляд меню з фотографіями, вибір модифікаторів (напр. "без цибулі", "рослинне молоко"). Можливість замовити та оплатити прямо за столиком (Apple Pay, Google Pay, Card). * Мультимовність: Підтримує будь-які мови без обмежень (адаптується під мову браузера клієнта або обирається вручну).

2. Ролі та доступи (Модульна система)

Система використовує гранулярну (модульну) систему управління доступами, що дозволяє тонко налаштовувати права для кожного співробітника.

2.1. Базові ролі системи

  • Супер-адмін (Власник): Повний доступ ко всім налаштуванням системи, фінансовим звітам, інтеграціям та управління ролями. Не може бути видалений.
  • Франчайзі-партнери: Доступ для партнерів з обмеженими правами для управління виключно своїми філіями та перегляду їх статистики. Вони не мають доступу до глобальних налаштувань мережі.

2.2. Матриця прав доступу (Permissions Matrix) та Кастомні ролі

Реалізовано як складну інтерактивну таблицю в налаштуваннях (Settings View -> Team & Roles), яка дозволяє тонко налаштовувати доступи для 7 базових ролей: Waiter, Kitchen, Manager, Franchise, Marketing, Admin, Super Admin.

Доступні права доступу (Access Rights), розбиті по групах: * POS & Orders (Каса та Замовлення): * Take new orders (Прийом нових замовлень) * Accept payments (Прийом оплат) * Apply discounts (Застосування знижок) * Refunds & Voids (Повернення та скасування чеків) * View Kitchen Display (Доступ до екрану кухні) * Management (Управління закладом): * Access settings (Доступ до глобальних налаштувань) * Manage menu items (Управління позиціями меню, цінами, стоп-листами) * View sales reports (Перегляд фінансових звітів та аналітики) * Export data (Експорт даних та вивантаження) * Manage team & roles (Управління командою, зміна матриці прав)

Система дозволяє як використовувати дефолтні налаштування ролей, так і створювати абсолютно кастомні комбінації доступів для конкретних співробітників під час їх запрошення.

2.3. Запрошення співробітників

  • Флоу Invite Member: Введення email співробітника, вибір ролі з випадного списку, вибір філій, до яких надається доступ. Співробітник отримує лист з посиланням для реєстрації.

3. Аналітика та Головна сторінка (Dashboard)

Цей модуль поєднує оперативний моніторинг показників ресторану в реальному часі та глибокі звіти для менеджменту.

3.1. Що вже реалізовано (Dashboard)

Головний екран системи, який надає миттєвий зріз стану бізнесу. * Глобальні віджети метрик: Відображення Gross Sales (валова виручка), Net Sales (чиста виручка), Кількість чеків, Середній чек, Завантаженість залу (активні столи). * Мульти-локаційність: Інтеграція з Locale Switcher. Адміністратор може бачити єдиний зведений дашборд по всій мережі одразу, або вибрати конкретну філію (графіки автоматично перемальовуються під обрану локацію). * Графіки активності: Візуалізація динаміки продажів по годинах/днях за допомогою інтерактивних чартів. * Пошук з аналітикою (Search Modal): Виклик через ⌘K, який окрім навігації по додатку, показує коротку статистику продажів та популярні запити.

3.2. Що заплановано (Базові Звіти та Порівняння)

Окремий розділ звітів для моніторингу ключових показників бізнесу. * Порівняння періодів та локацій: Можливість порівнювати продажі за різні періоди (дні, тижні, місяці) та аналізувати ефективність різних філій між собою. * Статистика популярності страв: Простий звіт продажу позицій меню для розуміння, які страви приносять найбільший дохід, а які варто виключити (замість складного математичного ABC-аналізу). * Звіти по співробітниках: Базова статистика продажів по кожному касиру чи офіціанту. * Фінансові зведення: Звіти по закритих чеках, податкові зведення (для VERIFACTU) та логування скасованих транзакцій. * Експорт даних:* Можливість вивантаження звітів у прості формати (CSV, Excel).

4. Управління замовленнями та залом (POS Terminal)

Ядро системи для роботи персоналу в закладі, що поєднує візуальне управління залами з логікою обробки чеків.

4.1. Інтерактивний план ресторану (Tables View - SVG Canvas Engine)

Що вже реалізовано (Редактор залу): * Власний SVG-рушій: План будується не на статичних картинках, а на векторній графіці. Всі координати стін, зон та столів обчислюються математично (x, y, width, height, radius) та зберігаються в JSON. * Складні інструменти малювання: * Draw Zone / Draw Wall: Побудова залу по точках. Алгоритм автоматично замикає контур, якщо остання точка знаходиться близько до першої. * Add Table: Швидке додавання стандартних круглих та квадратних столів. * Draw Custom Table: Дозволяє намалювати стіл будь-якої складної геометричної форми (наприклад, кутовий диван чи овальну барну стійку). * Draw Element: Нанесення об'єктів інтер'єру (колони, сходи) для точності плану. * Математична точність (Snapping): Вбудовано алгоритми Snap to Grid (прилипання курсору до невидимої сітки) та Snap to Vertex (примагнічування до вже існуючих кутів для ідеально рівних стиків стін). * Вбудована рулетка: Під час малювання стін система динамічно вираховує та показує довжину кожної лінії в метрах. * Управління полотном (Canvas Controls): Повний контроль над масштабом — Zoom In, Zoom Out, інструмент "рука" для панорамування (Pan), та кнопка Recenter для скидання камери. * Мульти-рум: Система вкладок (Tabs) для перемикання між різними поверхами або залами (наприклад, Main Hall, Terrace, VIP Room). * Smart-захист: Банер "You have unsaved changes", який блокує випадкову втрату даних при спробі вийти з редактора без збереження. * Генерація QR-кодів: Вбудоване модальне вікно для кожного столика, де менеджер може згенерувати унікальний QR-код. Код автоматично рендериться у вигляді зображення, з можливістю одразу завантажити його у форматі .png для друку. Присутній захист (підтвердження) від випадкової регенерації нового коду, яка зробить старий надрукований QR недійсним.

4.2. Live POS View (Режим симуляції/роботи)

Візуальний контроль залу в реальному часі для офіціантів, касирів та хостес. * Життєвий цикл стола (State Machine): Столи на SVG-полотні динамічно змінюють свій колір залежно від того, що за ними відбувається: * Available (Сірий/Зелений): Стіл повністю вільний. * Occupied (Синій): За столом сидять гості, офіціант відкрив Draft-замовлення і почав набивати страви. * Billed (Жовтий): Рахунок (пре-чек) видрукувано і віднесено гостям, очікується оплата. * Dirty (Червоний): Оплату успішно проведено, але стіл фізично брудний. Офіціант має вручну перевести його в статус Available після прибирання посуду.

4.3. Обробка замовлень та Кухонний друк (Запланована логіка)

  • POS Термінал (Інтерфейс касира): Сторінка для швидкого створення замовлень та зміни кількості страв (quantity).
  • Коментарі для кухні: Можливість додавати текстові коментарі до кожної страви при замовленні (наприклад, "Без цибулі", "Подати через 15 хв"), які будуть видрукувані на чеку для кухаря.
  • Калькулятор чека: Застосування фіксованих сум або відсоткових знижок безпосередньо на конкретну позицію, або на весь чек в цілому.
  • Відмова від екранів KDS (Маршрутизація друку): Замість встановлення екранів на кухні (KDS) використовується класична та надійна система друку паперових чеків (встрєчок). Система автоматично відправляє напої на принтер бару, а гарячі страви — на принтер кухні.
  • Історія замовлень: Глобальний архів усіх транзакцій та чеків з можливістю пошуку по номеру, даті чи співробітнику.

5. Фінанси, Податки та Відповідність VERI*FACTU

Модуль створено з урахуванням жорстких вимог податкової служби Іспанії (Agencia Tributaria - AEAT) щодо запобігання фальсифікації даних ("software de doble uso").

5.1. Рух коштів та Інвойси

  • Каса (Cash Register): Жорсткий контроль фінансів на зміні.
    • Відкриття зміни: Фіксація початкового залишку готівки в касі (Float).
    • Закриття зміни (Z-звіт): Автоматичне звіряння системних продажів з реальними грошима. Фіксація недостачі (Shortage) або надлишку (Overage).
    • Внесення/Вилучення (Cash In/Out): Документування витрат готівкою напряму з каси (наприклад, оплата постачальнику за лід).
    • Історія оплат: Розбивка по методах (Готівка, Карта, Змішана оплата, Оплата бонусними балами).
  • Інвойси (Facturas): Конвертація звичайного фіскального чеку (ticket) в офіційну фактуру формату А4 (PDF).
    • Передбачає введення податкових даних клієнта (NIF/CIF, Назва компанії, Адреса).
    • Має власну автоматичну секвенцію нумерації, окремо від чеків.

5.2. Архітектура VERI*FACTU (AEAT Іспанія)

  • Незмінність даних (Append-only Ledger): Заборона видалення чеків. Скасування замовлення можливе виключно через створення компенсаційних чеків.
  • Журнал аудиту (Audit Trail): Логування всіх дій касира.
  • Підготовка до відправки XML: Структура бази даних готова до генерації податкових звітів та майбутньої асинхронної відправки в податкову (Message Queue).
  • QR-коди на чеках: Динамічні QR-коди згідно з вимогами іспанського законодавства.

6. Налаштування системи та Управління Меню (Menus View)

Гнучкий інструментарій для створення ієрархії меню, кастомізації закладу та налаштувань терміналів.

6.1. Налаштування та Глобальні параметри

  • Управління пристроями: Реєстрація та контроль підключених планшетів (POS) та IP-принтерів. Можливість віддалено прив'язати принтер до конкретної зони (Кухня 1, Кухня 2, Бар) або відправити тестовий друк.
  • Профіль та UI-Налаштування: Завантаження аватарів, швидке перемикання тем (Light/Dark mode) та мов інтерфейсу панелі (Англійська, Іспанська, Каталонська, Російська) через глобальний State без перезавантаження.
  • Звукові Пуш-сповіщення (Notifications): Налаштування візуальних та звукових алертів для системних повідомлень або нових задач. Забезпечує миттєву реакцію персоналу навіть у галасливих умовах (кухня/бар).

6.2. Структура Меню та Редактор Страви

  • Налаштування меню (Drag & Drop): Створення необмеженої кількості категорій (напр. "Breakfast", "Desserts"). Повна підтримка візуального сортування категорій та карток страв мишкою за допомогою Framer Motion (плавні мікроанімації перестановки).
  • Редактор Страви (Advanced Dish Modal):
    • Мультимовний інтерфейс: Вбудований перемикач вкладок (EN, ES, RU) для введення локалізованих назв та описів страв у єдиній формі (в коді працює як єдиний об'єкт стану { en: '', ru: '', es: '' }).
    • Медіа: Інтерфейс для завантаження фотографій страв з локальним прев'ю.
    • Варіативне ціноутворення: Можливість задати як фіксовану ціну (Single Price), так і створити варіації (Variants) та окремі модифікатори до страви.
    • Алергени: Вбудована система додавання стандартних (Dairy, Nuts) або створення кастомних алергенів.
  • Версіонування меню (Price History): Історія версій меню — при зміні цін зберігається історичність (можливість знати, яка ціна була в момент конкретного замовлення).
  • Динамічне оновлення (Стоп-листи): Швидкий тогл видимості (Visible/Hidden) безпосередньо в хедері модалки страви. Дозволяє менеджеру приховати позицію з меню з обов'язковим підтвердженням дії (Toggle Confirmation), щоб уникнути випадкових кліків.

6.3. Модифікатори та Алергени

  • Групи модифікаторів (Global Modifiers): Гнучкий конструктор страв. Наприклад, створення групи "Молоко" з лімітами: обов'язково вибрати 1 варіант (Коров'яче 0€, Вівсяне +1€). Або групи "Добавки до бургера" (Min 0, Max 3).
  • Глобальні алергени: Єдиний довідник алергенів. Менеджер просто проставляє галочки (горіхи, лактоза, соя) біля страви, а система автоматично виводить яскраві попередження клієнтам, дотримуючись європейських стандартів безпеки харчування.

7. Програма Лояльності та CRM (Loyalty Program)

Повноцінна маркетингова платформа для залучення та утримання гостей, інтегрована безпосередньо в POS.

7.1. База гостей (CRM & Customer Data Platform)

  • Розширений профіль гостя: Об'єднує транзакційну історію клієнта з усіх філій мережі. Збирає метрики: LTV (Lifetime Value), середній чек, частота візитів, улюблені страви, наявність алергій, день народження.
  • Сегментація аудиторії: Інструмент для фільтрації бази (наприклад: "Гості, що не були більше 30 днів", "Гості із середнім чеком > 50€") для подальших маркетингових розсилок.
  • Ідентифікація: Швидкий пошук клієнта на POS-терміналі за номером телефону, email, іменем, або шляхом сканування його персонального QR-коду (який гість може додати в Apple Wallet / Google Wallet).

7.2. Маркетинг: Знижки, Акції та Сертифікати

  • Гнучка система знижок (Discount Engine):
    • Типи: Фіксована сума (напр. -5€) або відсоток (напр. -10%).
    • Сфера дії: На весь чек в цілому, на конкретну категорію (тільки на "Десерти") або на обрану страву.
  • Smart Акції (Happy Hours): Налаштування правил знижок за розкладом. Наприклад: "Знижка 20% на коктейлі з 18:00 до 20:00 щоп'ятниці". POS-термінал автоматично застосує знижку без участі касира, виключаючи людський фактор (fraud prevention).
  • Вирішення конфліктів: Якщо на один чек діють 2 акції одночасно, система автоматично перевіряє правила пріоритетів (або застосовує найбільш вигідну для клієнта, або блокує "знижку на знижку").
  • Подарункові Сертифікати (Gift Cards): Продаж та облік цифрових сертифікатів. Завдяки хмарній синхронізації, гість може купити сертифікат у Філії А, а витратити його залишок у Філії Б.

7.3. Бонусна система (Кешбек)

  • Накопичення балів: Автоматичне нарахування налаштованого відсотка від суми оплаченого чека на віртуальний рахунок гостя.
  • Списання (Pay with Points): Можливість повної або часткової оплати замовлення балами. Валютний курс балів налаштовується глобально (наприклад, 1 бал = 1 євро).
  • Багаторівнева програма (Tiers): Можливість створення статусів лояльності ("Silver", "Gold", "VIP"), де відсоток кешбеку динамічно зростає залежно від загальної суми LTV (суми, яку клієнт витратив у закладі за весь час).

8. Склад та Інвентаризація

  • Улік та Інвентар: Ведення обліку товарів (мерч, базові речі для кухні та бару). Наявність повноцінного складу в додатку (відображення залишків).
  • Логістика: Переміщення речей між локаціями (філіями) — мерчу, позицій кухні та бару. Контроль залишків, прибуткові накладні, ручне та автоматичне списання при продажу.

9. Контроль Якості, Задачі та Інтеграції (Operations & Integrations)

Комплексний модуль для контролю за дотриманням стандартів мережі та взаємодії із зовнішніми сервісами.

9.1. Операційний контроль та Задачі

  • Цифрові Чек-листи (SOPs): Створення кастомних щоденних чек-листів для відкриття, закриття або передачі зміни (наприклад: "Увімкнути кавомашину", "Перерахувати касу", "Перевірити туалети").
  • Фото-звіти (Photo Proofs): Для критичних задач менеджер може налаштувати обов'язкове прикріплення фотографії з камери POS-планшета (наприклад, фото чистого залу чи вітрини десертів після закриття) для уникнення формального "проклікування" задач.
  • Менеджмент задач (Task Manager): Внутрішня система To-Do для персоналу. Головний офіс може ставити локальні задачі на конкретну філію з дедлайнами та відслідковувати відсоток їх виконання.

9.2. Інтеграції з Delivery Агрегаторами (Uber Eats, Glovo)

  • Прийом замовлень: Проста базова інтеграція. Замовлення з сервісів доставки (Glovo, Uber Eats) надходять напряму в єдину систему POS, що позбавляє касира необхідності вручну перебивати чеки в систему.

9.3. Управління Репутацією (Google Maps & TripAdvisor)

  • Агрегація відгуків: Збір та відображення відгуків клієнтів з Google Reviews та TripAdvisor у єдиному дашборді.
